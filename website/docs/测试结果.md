## Android 协作约定检查

本轮没有修改 Android 源码、资源、Room Schema 或构建定义。按项目要求执行 `test`、`lint`、`assembleDebug`、`assembleRelease`。

首次 Gradle 调用受沙箱缓存写权限限制；获准重试后出现已知 `Unable to establish loopback connection`。随后设置仅当前进程的项目内 TEMP/TMP 和 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=D:/AndroidProjects/LizhangApp/build/docs-site-check-tmp`，执行到了实际编译、测试和打包。

| Debug 单元测试 | 155 项，151 通过、4 失败；全部失败位于现有 `StartupAnimationViewModelTest` |
| Release 单元测试 | 155 项，151 通过、4 失败；与 Debug 同样四项 |

由于单元测试任务失败会阻止后续任务，分别运行 Release 测试和剩余 lint/打包任务，最终打包命令返回 `BUILD SUCCESSFUL`。不把两种测试各四项失败写成全量通过。

失败证据位于 `app/build/test-results/testDebugUnitTest/TEST-com.yangsong.lizhang.ui.viewmodel.StartupAnimationViewModelTest.xml` 及对应 `testReleaseUnitTest` 文件。失败方法涉及：

- 一致快照与窗口帧时间线；440ms 时预期 0.5，当前 900ms 动画时长下为 0.4888889。
- 配置重建保留时间轴；同样的进度预期不一致。
- 首次可见绘制等待；同样的进度预期不一致。
- Release 关闭诊断保持固定时长；测试在 880ms 预期结束，当前时长为 900ms。

测试与当前实现的时长预期不一致。测试后续还包含窗口就绪状态预期，首个失败解除后需继续核对；本轮未擅自更改启动动画或测试。Android 代码检查与打包不代替权限撤回、厂商后台通知、系统换机、文件提供方或真机动画验收。
