# 颜色渐变锁生命周期修复

## 问题与结果

对 `cb19acb` 整合版本的静态审查发现：颜色请求的固定 1500ms 超时会直接清除请求，却保留 `animateColors=true`；请求 ID 变空后 Compose effect 会重新启动未完成的渐变，形成无锁播放。系统高倍率动画下，后续主题输入可能在原动画完成前被接受。

本轮只修复颜色渐变与请求锁的衔接。保留原有 240ms 渐变及曲线、系统动画倍率、420ms 圆形扩散、圆心规则和语言交接；不改变配色、设置页设计、业务数据、Room、备份或权限。

## 请求阶段与释放顺序

| 阶段 | 行为 | 释放条件 |
| --- | --- | --- |
| 等待 `WAITING` | 占用原有主题锁，等待实际主题与请求目标一致；1500ms 只保护此阶段 | 正常进入播放；等待超时只转入收敛，继续持锁 |
| 播放 `RUNNING` | Compose 认领实际动画执行后取消等待定时器，沿用真实动画时钟和系统倍率 | 当前请求、宿主及执行编号匹配，配色真正到达目标 |
| 收敛 `SETTLING` | 超时使旧执行完成回调失效；新 effect 取消旧渐变并 `snapTo` 当前实际生效的主题 | 收敛完成回调确认后才释放锁 |

同一请求的 effect 重启也会分配新的执行编号。旧请求、旧宿主、旧执行以及重复完成回调均不能释放当前锁。播放期间实际主题改变时，转为对当前有效主题收敛；协程取消不在无条件 `finally` 中解锁，由新执行或现有宿主取消／解除流程接管。

没有有效颜色请求时，Theme 只同步最终配色；清除颜色请求同时关闭 `animateColors`，请求消失不再启动新渐变。异常颜色动画会先收敛再报告完成；前后台、导航离开、宿主解除及语言中断继续沿用原有取消入口。
