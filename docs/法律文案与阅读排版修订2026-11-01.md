## 排版来源核查

源码可确认的情况如下：

- 两个阅读入口原先均直接使用 `MaterialTheme.typography.bodyLarge`。`Type.kt` 的该样式指定 `16sp / 24sp`，没有指定 `fontFamily`、`letterSpacing` 或 `textAlign`；应用源码也没有为这两处正文设置 `TextAlign.Justify`。
- 静态读取本机依赖源代码：Compose UI Text `1.8.3` 的 `SpanStyle.kt` 将未指定字距解析为 `0sp`，未指定字体解析为 `FontFamily.Default`；`ParagraphStyle.kt` 将未指定对齐解析为 `Start`。正文没有从 Material 默认字号令牌取得 `0.5sp` 字距，不能把截图问题归因于该值或两端对齐。
- 原解析器只保留“章节标题 + 整节字符串”，小标题被当作普通正文，列表保留文本前缀。两处页面分别渲染标题及单个正文 Text，段落依靠空行区分，缺少可统一控制的小标题和列表排版。权限段落较长的问题可以从源文件直接确认。
- 字体由系统默认字体及其回退决定。仅靠源码无法确定本人手机的字体设置、厂商字体度量及其对字面疏密的影响。本轮没有读取设备设置、采集新截图或进行渲染验收，不宣称已确认所有视觉字距问题的设备原因。

`0sp` 是本次明确规定的局部样式，不能描述为把已确认的非零字距改为零。可确认的改进是：明确法律阅读所用的字体族与参数，并将段落、小标题和列表分别排版；实机观感仍待本人验证。

## 统一正文呈现

新增 `LegalDocumentTypography`，仅由法律阅读组件和首次告知的文档标题使用，原 `Type.kt` 与全局 `LiZhangTypography` 不变。

| 层级 | 字号 / 行高 | 字重与间距 |
| --- | --- | --- |
| 告知中的文档标题 | 22sp / 30sp | 粗体 |
| 章节标题 | 18sp / 28sp | 半粗体 |
| 小标题 | 16sp / 26sp | 半粗体，上方另留 8dp |
| 正文与列表 | 16sp / 26sp | 常规字重，各文本块之间留 12dp |

正文明确使用 `FontFamily.SansSerif`、`letterSpacing = 0.sp`、`TextAlign.Left` 和自然换行。该字体族仍依赖 Android 字体及中文回退，不承诺在所有厂商设备上呈现完全相同的字形。字号和行高继续使用 sp，跟随系统字体缩放，不限制正文行数或高度。

首次告知与独立全文页均调用 `LegalDocumentSectionContent`，帮助文档也沿用该组件。正文颜色使用主题的 `onSurface`，合并主题样式以保留既有过渡阴影；未修改主题动画、语言切换、页面容器或业务流程。七语言界面继续读取同一完整中文正文，原有语言提示规则不变。

每节的标题、段落和列表放在同一个 `SelectionContainer` 中，保留选择复制；章节与小标题保留无障碍标题语义。列表标记与正文分列，换行后正文保持缩进；有序列表保留源编号，不自动从 1 重新编号。

## 解析与测试源码

`LegalDocumentParser` 保留章节、小标题、段落及列表的结构，同时保留用于全文完整性检查的纯文本 `body`。当前文档使用的标题、强调、行内代码、链接、表格及列表均有对应处理：不显示井号、强调或反引号等语法标记，无序列表转换为圆点，有序列表保留编号，表格继续逐行展开，HTTPS 链接保留地址。本轮没有引入通用 Markdown 依赖。

`LegalDocumentTest` 将原来要求出现权限常量的预期改为自然语言名称，新增三个用例，分别覆盖：

1. 主动授权时机、预览与保存字段差异、拒绝行为、锁屏、重启与撤回权限。
2. 三份公开正文及解析结果无原始权限常量；开头邮箱去重；末尾联系、反馈邮件处理与权利请求完整。
3. 小标题、分段、列表结构和源编号保留，显示文本无 Markdown 标记。

原有加密、恢复替换、未成年人、版本、日期、网站备案、公开姓名隔离、内部审批字段隔离、链接与无联网权限等断言保留。没有删除测试、屏蔽断言或调整发布门禁。

独立全文的仪器测试原来通过一个整节字符串定位开篇 Text，现改为逐块滚动并检查开篇全部内容，适配段落拆分；原有导航、大字号、深浅色和七语言检查不变。测试代码只修改、未编译或运行。截图基准未生成或更新，现有首次告知截图须由本人重审。
