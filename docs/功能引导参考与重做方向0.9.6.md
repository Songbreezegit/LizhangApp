# 功能引导参考与重做方向（0.9.6）

日期：2026-10-08。已将原四步提示重做为十二步漫游演示，覆盖“新建联系人 → 记一笔 → 删除礼金 → 删除联系人”。复用真实 App 页面和原有 ViewModel，用户点下一步后才自动操作，每一步用功能气泡讲解。示例仅在独立内存中保存和删除，不写入正式账本。Debug、Release 新包已构建，设备验收交给用户。

## 当前问题

初稿只有四段进度、标题、说明和按钮；示意目标是一个空的轮廓。没有放进礼账的真实页面场景，也没有演示操作后的结果。四步只是换文字，缺少各自的视觉内容。继续给同一个气泡增加入场参数，无法补齐这些问题。

## 参考实例

### Clip设计夹：漫游式引导

用户提供的[小红书帖子](https://www.xiaohongshu.com/explore/68bfb045000000001b03f3dc)已在浏览器读取正文及第 6/14 页“漫游式引导”。该页将提示放在相关功能附近，并强调第一次接触时结合场景解释。正文还提出减少操作负担、允许自主学习节奏，以及先体验核心能力。

礼账据此采用可退出、可从设置重播的分步演示：每次由用户点下一步，再自动填写、保存、跳转或删除；不按计时自动推进。

### Apple：TipKit 官方示例

[WWDC24 视频](https://developer.apple.com/videos/play/wwdc2024/10070/)，约 1:18 展示指南针依次提示单击定位、长按回正；约 8:25 展示旅行步道图片与说明组成的自定义提示样式。这是官方示例 App，不是实际消费产品截图。

借鉴：一个场景对应一个动作，说明操作后的结果；提示可以包含功能示意，外观与宿主 App 一致。

### Microsoft：Fluent 2 Onboarding

[官方图例](https://fluent2.microsoft.design/onboarding) 的 Orient 展示品牌色锚点提示，Explain 展示 Teams 空状态与操作入口；说明强调可跳过、之后可返回、在相关任务中逐步解释。

借鉴：把真实入口、用户收益和明确动作放在一起；卡片继续复用礼账自己的材质、字体和按钮。

### Google：Material 功能发现

[官方动效示例](https://m1.material.io/growth-communications/feature-discovery.html) 展示从目标图标出现、目标轻脉冲、点击后扩散淡出以及多步操作完成反馈。页面属于历史 Material 1；借鉴交互节奏，不直接套用旧版大面积彩色圆形视觉。

借鉴：让用户知道提示对应哪个真实入口；动效明确表达“出现、关注、操作完成”的先后关系。

### Duolingo ABC：实际流程动效记录

[60fps 收录的 Get Started 流程](https://60fps.design/shots/duolingo-abc-get-started) 展示角色待机、按钮按压、选择反馈、页面转场和进度变化。这是第三方产品录屏参考。

借鉴：品牌角色和操作反馈可以贯穿流程；礼账采用更克制的幅度与节奏，避免让用户等待长动画。

## 礼账的落地方向

直接复用 ContactsScreen、ContactEditorScreen、ContactDetailScreen、AddGiftScreen 和 GiftRecordDetailScreen，以及它们原有的 ViewModel，不另画一套示例页面。米白、陶土橙、暖灰、圆角、半透明材质和浅深色继续来自 App；每步提示只解释当下的操作。

| 步骤 | 原页面 | 下一步执行的动作 |
| --- | --- | --- |
| 1 | 联系人列表 | 打开新建联系人页 |
| 2 | 空联系人表单 | 自动填写“示例小礼”、关系“朋友”与练习备注 |
| 3 | 已填联系人表单 | 调用原保存流程，将示例保存到演示内存 |
| 4 | 联系人详情 | 查看零往来统计，再打开记一笔 |
| 5 | 空礼金表单 | 自动填写 200 元、收到、生日与示例备注 |
| 6 | 已填礼金表单 | 调用原保存流程，显示成功反馈并进入礼金详情 |
| 7 | 礼金详情 | 打开礼金删除确认 |
| 8 | 礼金删除确认 | 调用原删除流程，删除内存中的示例礼金 |
| 9 | 礼金删除后的联系人详情 | 查看统计与往来记录变化，进入联系人编辑页 |
| 10 | 联系人编辑页 | 打开联系人删除确认 |
| 11 | 联系人删除确认 | 调用原删除流程，删除内存中的示例联系人 |
| 12 | 已清空的联系人列表 | 完成引导并退出演示 |

首页保留可选邀请与“稍后再说”；开始演示后，功能气泡常驻“演示模式 · 示例不会保存”和当前步骤序号，可收起说明查看底页，也可随时退出。底页保留原布局、统计与保存成功反馈，演示期间只由气泡或确认框里的下一步推进，避免误触实际表单而跳过讲解。

每一步重新展开功能说明，等待当前页面及删除结果显示后再启用下一步。删除确认阶段将功能气泡放入同一模态窗口，并保留错误和退出按钮；关闭确认窗口也会退出引导。页面内部的保存反馈与选择状态不参与进程恢复，重新打开演示从空练习空间开始。

真实编辑 ViewModel 通过领域接口 `GuidePracticeRepository` 注入独立 `GuidePracticeStore` 的内存 ContactRepository / GiftRecordRepository，实现相同保存和删除接口，不接 AppContainer 的真实仓储、Room、文件、日志或网络。联系人与礼金共用一个快照，统计、关联查询和删除反馈均从这个快照计算；专用负数 ID `-101 / -201` 仅在当前演示中使用。末尾先删除礼金，再删除联系人；退出或销毁先清理子 ViewModel，再清空空间，进程重启重新从第一步开始。设置中的“使用引导”可重新播放，完成偏好仍只由既有 OnboardingRepository 保存，已完成的升级用户不强制重播。

页面入场 260ms、曲线 `(.2, 0, 0, 1)`，透明度 `0 → 1`、横向位移 `24dp → 0`；操作气泡 240ms、App 源码曲线 `(.4, 0, .2, 1)`，透明度 `0 → 1`、竖向位移 `8dp → 0`，每步只入场一次。系统关闭动画时直接显示最终状态，不按计时推进步骤。

[新版 Figma 气泡流程稿](https://www.figma.com/design/4BlDvZZVFb0moftVwiux3f?node-id=31-5610) 根节点为 `31:5610 / guide-automatic-tour`，覆盖十二步功能气泡；浏览器编辑器中已建立 24 条轨道、48 个关键帧，`0–240ms` 透明度 `0 → 100`、Y 从基准 `+8 → 0`。浏览器曲线尚未核实，不能据此声称它与 App 源码曲线完全一致。[旧六场景稿](https://www.figma.com/design/4BlDvZZVFb0moftVwiux3f?node-id=31-694) 根节点 `31:694` 已标为静态参考，不再作为 App 页面实现依据。
