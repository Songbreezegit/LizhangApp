# 本地通讯录批量导入 V1

## 范围与架构

从远程 main 基线 `8fbdb4c264c29c47bcaf70c61f5927c5cc408244` 创建 `feat/contact-import-v1`。保留原列表、搜索、排序、新增按钮和详情，仅增加入口与 `contact_import` 路由。

`ContactImportScreen → ContactImportViewModel → DeviceContactRepository / ContactRepository ← DeviceContactDataSource / RoomContactRepository`。Compose 仅处理界面、权限与导航事件；系统查询在数据层通过 `ContactsContract.CommonDataKinds.Phone` 进行。查询使用 IO，清洗、排序、搜索使用 Default。列表使用稳定号码键的 LazyColumn，按钮在写入期间禁用。

## 权限与隐私

- Manifest 新增 `READ_CONTACTS`，无 `WRITE_CONTACTS`、无 `INTERNET`。
- 首次启动不请求权限；主动进入导入页面后通过 Activity Result `RequestPermission` 请求。
- 拒绝时显示解释与重新授权；不再询问时提供系统应用设置及返回联系人。设置返回后重新检查权限。
- 系统号码和姓名仅保留于页面 ViewModel 内存，不写日志、缓存、SavedStateHandle 或统计服务。权限状态只持久化“曾请求”布尔值。
- 预览包含姓名和脱敏号码，选中并确认后才保存完整号码为普通 Contact。不写入系统联系人标识、来源或头像。
- `allowBackup=false` 与原有自动备份/换机迁移排除规则保持不变。用户主动本地备份仍包含已导入记录，备份与 CSV/XLSX 格式不变。
- 发布说明应披露通讯录读取权限及本机处理用途；隐私页面已同步说明读取范围和用户选择后的保存行为。

## 清洗与重复判断

姓名去除首尾空白；空姓名、空号码、无效号码排除。号码清理空白、连字符、括号、句点，仅接受可选前导加号和 3–15 位数字。大陆 `+86` 后为 11 位 `1[3-9]` 手机号时移除国家码，其他号码保留国家码和前导零。V1 不解析分机、字母号码或拨号控制字符。

候选按标准化号码去重，同一系统 CONTACT_ID 下不同号码独立保留。统一 DuplicateIndex 优先比较标准化号码，再比较去除首尾空白后的姓名（精确一致）：

| 状态 | 条件 | 默认选择 | 用户操作 |
| --- | --- | --- | --- |
| EXISTING | 标准化号码相同，不论姓名 | 否 | 禁止选择和导入 |
| POSSIBLE_DUPLICATE | 姓名相同但号码不同，或礼账原联系人无号码 | 否 | 显示“同名联系人”，可手动选择 |
| NEW | 姓名和号码均未匹配 | 是 | 可取消或重新选择 |

全选是用户主动选择，包括可能重复项，不包括 EXISTING。搜索不清空隐藏选择。不修改、覆盖或合并原联系人；手动确认的同名项只新建独立联系人。

`ContactRepository.importDeviceContacts` 提交完整候选和选择快照，DAO 的 `@Transaction` 内读取最新联系人、重新执行三类判断、按标准化号码去重，再调用一次 `insertAll`。并发导入由 Room 事务串行化，失败整批回滚，不修改现有外键。原 `createAll` 批量接口继续保留。

结果统一展示成功数、已存在跳过数、可能重复但未选择数，统计范围为本次完整有效候选，不受搜索过滤影响。无效项与系统通讯录内部同号项不重复计数。页面打开后新增的同号记录禁止导入；原 NEW 项若在提交时变成同名冲突，本次取消默认选择并计入可能重复未选择，重新进入预览后可明确手选。只有预览已提示同名且用户选中的项允许按可能重复导入，防止数据库变化导致默认选择绕过提示。

- Compose 仪器测试：拒绝/永久拒绝、空列表、已存在禁选、长姓名、脱敏、联系人入口到假通讯录导入成功后返回刷新。
- 测试仅使用虚构数据和可注入的 DeviceContactRepository；不得读取开发者真实通讯录。

## 验收关注点

真机补充验证不同厂商系统权限弹窗、首次拒绝与永久拒绝、设置授权后返回、系统撤销权限、旋转与后台恢复、3000 条候选滚动与搜索。原有手动新增联系人不改变重复策略；导入事务保证本批次与写入前数据去重，不增加唯一索引。
