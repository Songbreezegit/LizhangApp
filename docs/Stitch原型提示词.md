# 礼账 App：Stitch 原型提示词

## 使用方法

先使用“全局提示词”生成一个完整方向，再分别使用页面提示词补齐页面。建议生成 3 个风格方向，只选择一个继续深化。选定方向后导入 Figma，整理为变量、组件和可点击流程；不要直接使用 Stitch 导出的 HTML/CSS 作为 Android 代码。

## 全局提示词

```text
设计一款中文 Android 原生应用“礼账”，用于记录家庭礼金和人情往来。主要用户是 45～65 岁、长期使用纸质礼簿的中国用户，他们不熟悉复杂 App。

产品不是普通财务记账软件，而是现代家庭礼簿。核心目标是快、简单、可靠：新增一条记录不超过 3 步，联系人历史记录能快速查询，数据保存和导入过程必须让用户安心。

请使用 Material 3 的 Android 移动端设计语言，设计 Pixel 9 尺寸的高保真中文界面。视觉气质温暖、可信、克制，有现代纸质礼簿的感觉。使用暖白背景、砖红品牌色、中等圆角、清晰的大字号和宽松点击区域。避免过度装饰、玻璃拟态、霓虹色、复杂渐变和只靠图标表达操作。

底部导航包含：首页、联系人、统计、设置。首页突出“新增礼金”主操作，并提供搜索和 OCR 导入快捷入口。金额必须同时使用文字标签和颜色区分收到/送出。所有用户可见文字使用简体中文。

请保持统一的颜色、字体、间距和组件规则，并为页面补充空状态、加载状态和错误状态。需要设计：首页、新增礼金、联系人、联系人详情、搜索、统计、OCR 待确认、设置。
```

## 首页提示词

```text
为“礼账”设计首页。顶部是礼账标题和明确的搜索入口；页面最重要的操作是大而醒目的“新增礼金”按钮。提供“拍照导入”“联系人”“统计”三个中文快捷操作。本年摘要展示收到、送出、净往来，最近记录展示姓名、事件、日期、收到或送出标签、人民币金额。信息层级清楚，适合中老年用户，不要让首页像专业财务仪表盘。同时生成首次使用的空状态版本。
```

## 新增礼金提示词

```text
为“礼账”设计新增礼金页面。字段依次为姓名、金额、日期、事件类型、收到/送出、备注。姓名可搜索已有联系人，也可以快速新建；金额使用适合数字键盘的大输入框；收到/送出使用文字清楚的分段选择；事件类型包含婚礼、满月、生日、乔迁、节日、白事、其他。底部固定主要按钮“保存记录”。请展示正常状态、字段错误状态和保存成功反馈，确保用户最多 3 步完成核心输入。
```

## 联系人与详情提示词

```text
为“礼账”设计联系人列表和联系人详情。联系人列表支持姓名或手机号搜索，每项展示姓名、累计收到、累计送出、净往来，优先突出姓名和最近往来。联系人详情顶部展示联系人信息和三项金额汇总，下方历史记录按年份分组，单条记录包含事件、日期、方向、金额和备注摘要。提供“新增往来”和“编辑联系人”文字操作。生成空记录和无搜索结果状态。
```

## 搜索与统计提示词

```text
为“礼账”设计搜索和统计页面。搜索支持姓名、手机号、备注，结果按联系人归组并突出匹配文字。统计支持本年、上一年和自定义年份，展示收到、送出、净往来，并按事件类型和联系人统计。图表旁必须显示清晰的中文标签与精确金额，不能只依赖颜色。整体保持易读，不做专业财务软件式复杂图表。
```

## OCR 待确认提示词

```text
为“礼账”设计 OCR 礼簿导入流程：选择拍照或相册、识别中、待确认列表、导入结果。重点设计待确认列表，每条识别结果都能编辑姓名、金额、日期，能删除错误条目；低置信度字段用温和但明显的中文提示标记。底部显示待导入条数和“确认导入”按钮，同时提供取消。必须让用户明确知道 OCR 结果不会自动写入数据库。生成识别失败、无有效记录、部分导入失败状态。
```

## 设置提示词

```text
为“礼账”设计设置页面。分组包含数据备份与恢复、Excel/CSV 导出、主题、字体说明、关于与隐私。备份、恢复等高风险操作使用清楚的解释文字；恢复数据前必须二次确认。页面简洁，使用标准 Android 设置列表，不添加账号、云同步、会员或社区入口。
```

## 反向约束

如果生成结果出现以下问题，继续要求 Stitch 修正：

- 删除英文、繁体字和无意义占位文字。
- 减少底部导航数量，不超过 4 项。
- 放大正文和点击区域，确保适合中老年用户。
- 减少装饰性卡片和渐变，突出新增、搜索、OCR 三个核心任务。
- 不要加入登录、会员、云同步、预算、社区或聊天功能。
- OCR 结果必须先确认和编辑，不能直接导入。
