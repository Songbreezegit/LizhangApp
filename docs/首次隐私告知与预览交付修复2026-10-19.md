## 文档失败的源码原因与处理

上轮新增的运行时模板正则 `\{\{([a-z_]+)}}` 未转义字面右花括号，原 Markdown 链接正则也使用了 `[^]]` 和未显式转义的右方括号。Android 的 java.util.regex 通过 ICU 实现；ICU 对字面花括号和集合内方括号的转义要求不能依据桌面 JVM/Node 的构建表现推定。异常在原 ViewModel 的 `catch (_: Exception)` 中仅变成 failed=true，没有错误类型可供定位，而首次告知又将两份文档的 canConfirm 与同意按钮绑定，形成永久无法继续的交互。

上述是源码中定位到的兼容缺陷及阻塞链路。本轮没有设备异常日志或运行复现，不能声称已确认用户设备上的全部触发因素，也不将构建成功写成故障已通过实机验收。

本次处理：

1. 新增构建任务 `generateOfflineLegalAssets`，在编译打包前从唯一 Markdown 源及共享元数据用普通字符串替换生成完整正文，同时核对常量、元数据、批准文件及正文版本。缺字段/残留模板或版本不符时拒绝生成，正式批准门禁继续独立保留。
2. 主资产输入改为生成目录，APK 的 `assets/legal/*.md` 是展开后的完整正文，原始模板不混入同一路径；Lucide 许可等其他既有资产原样复制。生成输出不提交 Git。
3. AssetLegalDocumentRepository 仅读取完整资产并做空白/残留字段防护，不在运行时读 Properties 或执行模板正则。LegalDocumentParser 的链接格式用字符串位置解析，移除这条路径上的正则编译。
4. 发生故障仍显示离线阅读错误和重试。Debug 仅记录固定文档类型、读取/检查/解析阶段、异常类型及应用源码文件/行号；不记录异常 message、完整堆栈、正文、元数据值或个人数据。ViewModel 的 Debug 错误状态仅保留文档与错误类型，Release 不展示诊断详情，取消协程仍正常抛出。

源码依据：[Android Pattern 的 ICU 实现入口](https://android.googlesource.com/platform/libcore/+/refs/heads/master/ojluni/src/main/java/java/util/regex/Pattern.java)、[ICU 正则元字符与转义说明](https://unicode-org.github.io/icu/userguide/strings/regexp.html)。阅读官方源码/文档不等于运行测试。

## 官网预览交付

本轮只交付本机审核包，没有启动预览进程，没有浏览器或 HTTP 验收，没有提供已验证可访问的平台网页入口。`127.0.0.1` 指浏览器所在的电脑，不能用远程执行器回环地址代替用户 Windows。

ZIP 包含完整 `dist/`、`scripts/preview.mjs`、`START-PREVIEW.cmd` 和简明 `README.txt`。启动器先进入自身目录、检查 Node 是否可用，再在当前窗口运行服务，不自动打开浏览器或请求网络；端口被占用时显示错误，不结束其他进程、不修改防火墙。预览脚本仅在 listen 成功回调后打印“服务已启动”。

Windows 使用顺序：安装 Node.js 18 或以上 → 完整解压 ZIP → 双击 START-PREVIEW.cmd → 等待“服务已启动” → 在同一台电脑打开终端显示的地址。保留窗口，Ctrl+C 停止；停止后不能继续连接。也可在解压目录执行：

```powershell
node scripts/preview.mjs
```

默认端口 4173；占用时用 `node scripts/preview.mjs 4174`。只有本机服务实际启动后再打开相应回环地址；遇到 ERR_CONNECTION_REFUSED 先查看启动窗口，不能据此推断公网官网状态。

仓库重新构建和打包命令：

```powershell
node website/scripts/build.mjs --review
powershell -NoProfile -File website/scripts/package-preview.ps1 -ArchiveName 新的审核交付包.zip
```

打包脚本只复制约定的 11 个静态产物和启动辅助文件，不递归打包未知源码或私有文件；同名 ZIP 拒绝覆盖。审核包保留候选状态、noindex 与禁止抓取。ICP 仍为 `渝ICP备2026025309号-1`，生产门禁、待批准状态及 ECS 安全边界未放宽。
