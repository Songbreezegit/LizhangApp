# 自定义事件与悬浮栏 0.7.0

> 2026-09-23 验收返修已修正 Chip 行距与文案资源化，版本仍为 0.7.0 / 7，见 [返修记录](v0.7.0验收返修.md)。

## 起点与范围

分支 `feat/ui-refresh-v1`，开始前工作区干净，fetch 后基于 `7dbfe25332566c94707330a52284465b300f7d95`。本轮版本 `0.7.0 / versionCode 7`，保留蓝→暖白→浅橘渐变、透明 PNG 猫咪、导航交互及统计大类。

## 事件数据与交互

`GiftRecord`、`GiftRecordEntity`、编辑状态新增 `customEventName: String? = null`，稳定 EventType 枚举不变。预设事件和普通“其他”为 null，自定义“升学宴”为 OTHER + 升学宴。选择预设或普通“其他”会清空名称；编辑时完整回填。Dialog 去除首尾空白，空白与超过 20 个 Unicode 字符显示字段错误，允许中文、英文和数字。

统一领域规则 `eventDisplayText` 必须由调用方提供标准名称。UI 使用 `GiftRecord.eventDisplayLabel()` 读取资源，覆盖共享记录列表（首页、联系人详情、搜索、往来和日历）及礼金详情；CSV / Excel 使用导出包内固定中文映射，提醒使用 Context 资源映射。通知额外传递 `custom_event_name`。统计依然按 OTHER 归入“其他”。

## 数据库与备份

Room 版本 **2**；`MIGRATION_1_2` 执行 `ALTER TABLE gift_records ADD COLUMN customEventName TEXT DEFAULT NULL`，AppContainer 显式注册；没有 destructive migration。保留 schema 1，新增导出 schema 2。

MigrationTestHelper 从真实 schema 1 建库并写入虚构联系人和礼金，再迁移并按 schema 2 验证；打开迁移后的 Room 核对旧字段及新字段 null，并验证自定义名称写入、读取、备份与恢复。

普通备份 `FORMAT_VERSION = 3`，eventType 后写入可空 customEventName。读取 v1、v2 时不消费新字段且默认 null；独立旧版二进制布局测试验证兼容性。v3 往返保留自定义名称，密码加密层不变，恢复仍使用事务。

## 悬浮视觉与布局

- 浮动玻璃浅色 alpha **0.46**、深色 **0.60**；垂直渐变下端再降低 0.06，保持轻高光。
- 继续使用 FloatingRadius、1dp 描边和 FloatingElevation（6dp）；阴影只绘制在轮廓外，避免阴影内填充污染半透明区域。导航选中胶囊、按压与图标颜色动画保持原逻辑。
- 保存栏从 Scaffold.bottomBar 移至根 Box 覆盖层，左右 16dp、高 76dp、底部 8dp，统一处理 IME 和导航安全区。
- 正文仍占完整页面可用区域，底部增加 124dp 可滚动留白，备注可完全滚动到保存栏上方；内容可经过保存栏后方。
- 反馈同属覆盖层，与保存栏可视顶部相隔 14dp，不重新占用 Scaffold 高度；出现与消失不会压缩正文。成功依旧并行展示并等待 450ms 返回，失败保留输入且可重试。
- 验收返修移除误加的 top 12dp：方向到事件恢复 **18dp**；事件 FlowRow 的相邻行统一间距 **10dp**，横向仍为 8dp。
