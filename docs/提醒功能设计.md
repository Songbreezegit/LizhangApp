# 提醒功能设计

## 功能范围

礼账根据历史礼金记录的月日计算下一次年度日期，并在 Android 系统中调度本地通知。提醒只读取本地 Room 数据，不上传联系人或礼金信息。

当前支持以下提前档位：

- 当天
- 提前 1 天
- 提前 3 天
- 提前 7 天

用户还可以设置提醒时刻。开关、提前天数和时刻保存在应用私有的 `SharedPreferences` 中，联系人和礼金记录仍由 Room 管理。

## 分层职责

- `ui`：展示提醒设置并发送用户操作，不计算触发时间。
- `ViewModel`：组合即将到来的记录与提醒设置状态。
- `domain.reminder`：校验可选档位，处理年度日期、闰日、跨月和跨年计算。
- `domain.repository`：定义提醒设置与同步接口。
- `data.reminder`：持久化设置，通过 `AlarmManager` 调度通知，并在开机或应用更新后重新同步。

## 通知语义

当天提醒使用“今天是记录中的某事件日期”。提前提醒使用“距离记录中的某事件日期还有 N 天”，避免提前触发时仍显示“今天”的歧义。

每个待调度提醒会携带记录编号、联系人名称、事件类型和提前天数。关闭提醒时会取消应用记录的全部待触发闹钟。

每条系统通知使用记录编号生成独立的 `PendingIntent` 请求码和 URI，避免多个联系人的通知互相覆盖。点击通知时：

- 对应记录仍存在：直接进入该礼金记录详情。
- 对应记录已删除：回到首页，并在页面中央提示记录已不存在。
- 应用未启动：由 `MainActivity` 冷启动处理。
- 应用已在前台：通过 `singleTop` 和 `onNewIntent` 复用现有 Activity。

记录是否存在由专用 ViewModel 通过 Repository 查询，Compose 和 Activity 不直接访问 Room。

## 兼容与异常处理

- 历史版本的设置只有 0 天或 1 天，两种值继续有效。
- 如果本地设置因异常包含不支持的提前天数，读取时回退为当天提醒。
- 2 月 29 日在非闰年按 2 月最后一天计算。
- 提前日期跨越月份或年份时由领域层统一计算。
