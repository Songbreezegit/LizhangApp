# 独立提醒功能设计（0.9.2）

## 产品规则

提醒由用户在提醒页主动新增，不读取礼金表，不随“记一笔”创建、修改或删除。当天和过去的礼金记录均不会生成提醒。原来按历史礼金月日推导的自动闹钟在首次升级时取消，历史记录不迁移为独立提醒。

新增提醒包含名称与未来日期，默认只执行一次，可选“每年重复”。可编辑、单独停用或删除；系统通知总开关、当天或提前 1 / 3 / 7 天、统一时分控制通知调度。保存提醒不擅自开启通知权限。通知打开提醒列表，入口消费后配置重建不重复导航。

创建和保存只接受晚于设备本地今天的日期。错过触发时刻不补发，也不把一次提醒自动改成年度提醒。年度提醒寻找下一次未来触发时刻，非闰年 2 月 29 日按 2 月最后一天处理，按当前系统时区计算并处理夏令时。已通知日期及更早日期不重复消费。删除、停用、修改调度和关闭总开关均撤销旧闹钟；恢复开启只安排仍然有效的未来时刻。

## 页面

顶部保留原猫咪插画与玻璃风格，系统通知与提醒设置卡保持可用。下方“我的提醒”提供新增入口。空状态采用通知图标与简短说明，移除重复猫咪。提醒卡展示名称、一次/每年重复、下次日期或停用/已过时刻，并提供编辑、开关和删除确认。

中文、英文、日文、韩文资源同步维护；日期按应用语言显示。页面明确提醒仅保存在本机，不包含在礼金备份中。

## 分层与存储

- Compose 发送操作，`NotificationsViewModel` 组合独立提醒与设置。
- `IndependentReminderPlanner` 校验未来日期并计算下一次触发，无 Android 或数据库依赖。
- `ReminderRepository` 定义提醒 CRUD、设置、通知消费及调度。
- `AndroidReminderRepository` 在应用私有 SharedPreferences 保存独立提醒与最后通知日期，并使用 AlarmManager 调度。
- `ReminderCoordinator` 只观察提醒及设置，不订阅礼金记录；重复启动幂等。

Room 数据库版本 2、实体、迁移和礼金备份格式 3 均不变。独立提醒不进入旧礼金备份，不写公共文件或日志。系统备份继续禁用。原礼金通知导航协议保留兼容已有通知，新的通知进入提醒列表。

## 通知与异常

闹钟只携带提醒 ID、目标日期与触发时间，不携带联系人或礼金数据。广播发送前复核启用状态、通知权限、存在性、当前调度与目标日期，拒绝旧礼金闹钟、删除/停用后的广播、未来伪触发及重复通知。通知成功后保存消费日期；重复广播不会再次通知。应用重启、设备重启、日期/时间/时区变化后重新安排未来闹钟。

使用系统允许的非精确空闲闹钟，实际投递可能受系统省电策略影响。系统通知总开关关闭时提醒条目仍保留，单项开关表示该条目是否参与调度。
