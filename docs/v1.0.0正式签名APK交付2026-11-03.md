## 本地入口

使用 PowerShell 7.2 或更新版本执行 [构建脚本](../scripts/build-official-release.ps1)：

```powershell
./scripts/build-official-release.ps1 `
  -SigningPropertiesPath '<本人既有的非秘密签名配置路径>' `
  -FilingReportPath '<2026-10-21原备案公开报告路径>' `
  -JdkHome '<本机JDK目录>' `
  -AndroidSdkRoot '<本机Android SDK目录>' `
  -DeliveryDirectory '<仓库内被Git忽略的build/deliveries/v1.0.0-official-release目录>'
```

入口只读取配置中的 `storeFile`、`keyAlias`、可选 `storeType`，不按文件扩展名推断密钥库类型。先确认配置与原备案公开报告中的应用、别名、算法、位数一致，再由本人隐藏输入密钥库和 Key 密码；两者相同时 Key 密码直接回车。

JDK `keytool` 仅导出当前密钥库的公开 X.509 证书，复用既有备案脚本生成公开报告。当前证书的 SHA-256、MD5 及别名必须与原报告一致，且为 RSA 2048、有效期正常；仅比较模数不够。没有重新生成密钥，也不解析或上传私钥。

上述比对成功后，入口只确认 `filing_status`、`signing_identity_status`、`signing_certificate_sha256` 三个字段，并在密码进入 Gradle 环境前提交这一配置。正式包由该干净提交构建，之后的交付文档提交另行记录，不冒充产物源码提交。

密码只在本人终端隐藏输入：证书导出使用子进程环境，正式构建使用当前进程环境；不写 properties、参数、日志或报告，不进入 Git。Gradle 结束后立即清除密码变量并释放隐藏输入对象，失败同样清理。构建禁用配置缓存和扫描，不启用持久 Gradle Daemon。

正式命令保留 `--no-daemon --no-configuration-cache --no-scan -PofficialRelease=true :app:assembleRelease`，附加本机离线、单 worker 和进程内 Kotlin 编译参数。没有修改现有 Gradle 签名架构、`verifyOfficialReleaseContent` 或 `verifyReleaseSigning`。
