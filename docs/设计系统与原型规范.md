# 礼账 App 设计系统与原型规范

## 1. 本阶段目标

本阶段只确定信息架构、交互流程、视觉方向和可复用设计规则，不直接定稿最终 Compose 页面。设计完成后，Android 实现应复用现有 MVVM、Repository、Room 与 Navigation 架构，仅替换 UI 层。

## 2. 目标用户与设计原则

首批验证用户是开发者父母，他们长期使用纸质礼簿；产品的长期目标用户是有礼金、人情往来记录需求的广泛中文用户，而不是只面向中老年人的专用 App。首批用户用于验证产品是否足够简单可靠，不用于限制品牌审美和未来受众。界面必须满足：

- 快：核心任务最多 3 步完成。
- 简单：使用常见中文词汇，不依赖图标猜测含义。
- 清晰：重要金额、姓名和操作具有明确视觉层级。
- 宽容：删除、备份恢复等高风险操作必须二次确认并可解释。
- 可靠：保存、备份、恢复和导出必须显示清晰状态。
- 普适可用：点击区域不小于 48dp，正文建议不小于 16sp，支持系统字体缩放与深色模式；这些是通用易用性要求，不应表现为“老年模式”视觉。

## 3. 信息架构

一级入口建议使用 4 个底部导航项：

1. 首页
2. 联系人
3. 记一笔
4. 我的

“记一笔”作为底部主入口和首页悬浮操作；“搜索”位于首页顶部并可从联系人页进入。进入记一笔后切换为独立任务流，暂时隐藏主导航，用户通过保存或返回结束录入，避免未保存数据因误切页面而丢失。

## 4. V1 页面范围

### 首页

- 顶部：产品名、搜索入口。
- 核心操作：新增礼金。
- 快捷操作：收礼记录、送礼记录、日历和统计。
- 摘要：本年收到、本年送出、净往来。
- 最近记录：姓名、事件、日期、方向、金额。
- 状态：首次使用、无记录、加载中、正常、读取失败。

### 新增礼金

- 字段：姓名、金额、日期、事件类型、收到/送出、备注。
- 姓名支持搜索已有联系人和快速新建。
- 金额使用数字键盘，保存前显示格式化后的人民币金额。
- 表单内容独立滚动，并适配系统字体缩放。
- 主操作固定为“保存记录”，始终位于系统导航安全区与软键盘上方；保存过程中显示加载状态。
- 已经修改任一字段时，顶部返回和系统返回键先显示居中确认；“继续填写”为安全默认操作，“放弃填写”为明确的破坏性操作。
- 校验信息紧邻字段，不使用只闪现的提示。

### 联系人

- 支持姓名、手机号搜索。
- 列表展示姓名、累计收到、累计送出、净往来。
- 默认按最近往来排序，可切换姓名排序。
- 支持空状态、无搜索结果和加载失败状态。

### 联系人详情

- 展示联系人信息与收到、送出、净往来汇总。
- 历史记录按年份分组，记录展示事件、日期、方向、金额和备注摘要。
- 支持编辑联系人、新增往来和筛选记录。

### 搜索

- 同时搜索姓名、手机号和备注。
- 结果按联系人归组，并突出匹配内容。
- 最近搜索仅保存在本机，允许清除。

### 统计

- 时间范围：本年、上一年、自定义年份。
- 维度：收到/送出、事件类型、联系人。
- 图表必须同时提供文字数值，不能只依赖颜色区分。

### 设置

- 数据备份、恢复、Excel/CSV 导出。
- 主题与字体说明。
- 关于、版本和隐私说明。

## 5. 初始视觉方向

建议使用“简约中国古代风”：不是复古仿制品，而是把中国传统礼簿、书册和宋式审美中的秩序、留白与含蓄转译为现代 Android 界面。

- 基础风格：以 Material 3 的可用性和组件行为为底层，视觉上减少西式卡片堆叠，使用留白、细分隔线和书页式信息分区。
- 色彩：宣纸暖白、墨黑/黛色为基础，印章红作为品牌色和主要操作色；可少量使用低饱和青灰或茶褐，不使用大面积亮金色。
- 字体：页面标题和关键数字可尝试现代宋体/衬线气质，正文和表单使用清晰的现代无衬线中文字体；毛笔书法只可作为极少量品牌装饰，不能用于正文。
- 图形：可从印章、书签、线装书、回纹边界中提取极简几何元素，不直接堆叠古建筑、祥云、龙凤、铜钱等符号。
- 质感：允许非常轻微的纸张颗粒或水墨层次，但必须保证文字对比度和页面性能，不使用拟真卷轴或厚重纹理。
- 形状：圆角更克制，主要容器可采用小到中等圆角；分隔与对齐优先于大量悬浮卡片。
- 图标：使用统一的现代线性图标，必要时融入印章式方形轮廓，不使用复杂仿古插画替代功能图标。
- 品牌色：当前砖红方向调整为更克制的印章红，定稿前完成亮色与深色模式对比度检查。
- 背景：亮色模式为宣纸暖白，深色模式为暖墨黑，避免纯白与纯黑的大面积强对比。
- 金额：收到与送出除颜色外，还必须配合“收到/送出”文字和正负号。
- 动效：只用于保存成功、页面切换和列表变化，保持短且克制。
- 禁止方向：宫廷奢华风、红金婚庆风、武侠游戏风、国潮海报风、仿古网页风，以及为了“古风”牺牲信息密度和可读性的方案。

## 6. 设计令牌命名建议

Figma Variables 与 Compose 代码采用语义命名，不使用页面名或具体色值命名：

- 颜色：`color.brand.primary`、`color.surface.default`、`color.text.primary`、`color.amount.received`、`color.amount.given`、`color.status.error`。
- 间距：`space.1` 至 `space.8`，以 4dp 为基础步进。
- 圆角：`radius.small`、`radius.medium`、`radius.large`。
- 字体：`type.display.amount`、`type.title.page`、`type.title.section`、`type.body.default`、`type.label.action`。
- 模式：至少包含 Light 与 Dark。

定稿后再把令牌映射到 `Color.kt`、`Type.kt`、`Theme.kt`，避免在 Composable 中散落具体数值。

## 7. 原型验收标准

- 新用户能在 3 步内完成一条礼金记录。
- 从首页开始，3 秒内能找到联系人搜索入口。
- 关键按钮包含中文文字，不仅使用图标。
- 所有页面都有空、加载、错误和成功反馈方案。
- 设计覆盖 Pixel 9 常规尺寸，并检查较大系统字体下的布局。
- 颜色、字号、间距和组件均来自设计变量或组件库。
- Figma 中的最终页面、变量和组件状态足以直接映射到 Jetpack Compose。

## 8. 设计到开发的交付物

设计定稿时应提供：

- Figma 文件链接与版本说明。
- Light/Dark 两套颜色变量。
- 字体、间距、圆角和图标规范。
- 按钮、输入框、金额、记录列表、空状态、错误状态等组件及状态。
- 首页、新增礼金、联系人、联系人详情、搜索、统计和设置的高保真页面。
- 新增礼金、联系人管理和数据备份三个可点击原型流程。
- 设计验收截图和待开发差异清单。
