# 礼账 App 设计系统与原型规范

## 1. 本阶段目标

本阶段只确定信息架构、交互流程、视觉方向和可复用设计规则，不直接定稿最终 Compose 页面。设计完成后，Android 实现应复用现有 MVVM、Repository、Room 与 Navigation 架构，仅替换 UI 层。

## 2. 目标用户与设计原则

主要用户为 45～65 岁、长期使用纸质礼簿的家庭成员。界面必须满足：

- 快：核心任务最多 3 步完成。
- 简单：使用常见中文词汇，不依赖图标猜测含义。
- 清晰：重要金额、姓名和操作具有明确视觉层级。
- 宽容：删除、批量导入等高风险操作必须二次确认并可解释。
- 可靠：保存、备份、恢复和 OCR 导入必须显示清晰状态。
- 无障碍：点击区域不小于 48dp，正文建议不小于 16sp，支持系统字体缩放与深色模式。

## 3. 信息架构

一级入口建议使用 4 个底部导航项：

1. 首页
2. 联系人
3. 统计
4. 设置

“新增礼金”作为全局主要操作，在首页使用醒目的主按钮；“搜索”位于首页顶部并可从联系人页进入；“OCR 导入”位于首页快捷操作区。这样可以减少底部入口数量，同时保证高频任务一步可达。

## 4. V1 页面范围

### 首页

- 顶部：产品名、搜索入口。
- 核心操作：新增礼金。
- 快捷操作：OCR 导入、联系人、统计。
- 摘要：本年收到、本年送出、净往来。
- 最近记录：姓名、事件、日期、方向、金额。
- 状态：首次使用、无记录、加载中、正常、读取失败。

### 新增礼金

- 字段：姓名、金额、日期、事件类型、收到/送出、备注。
- 姓名支持搜索已有联系人和快速新建。
- 金额使用数字键盘，保存前显示格式化后的人民币金额。
- 主操作固定为“保存记录”，保存成功后提供查看详情或继续新增。
- 校验信息紧邻字段，不使用只闪现的提示。

### 联系人

- 支持姓名、手机号搜索。
- 列表展示姓名、累计收到、累计送出、净往来。
- 默认按最近往来排序，可切换姓名排序。
- 支持空状态、无搜索结果和加载失败状态。

### 联系人详情

- 展示联系人信息与收到、送出、净往来汇总。
- 历史记录按年份分组，记录展示事件、日期、方向、金额和备注摘要。
- 支持编辑联系人、新增往来和筛选记录。

### 搜索

- 同时搜索姓名、手机号和备注。
- 结果按联系人归组，并突出匹配内容。
- 最近搜索仅保存在本机，允许清除。

### 统计

- 时间范围：本年、上一年、自定义年份。
- 维度：收到/送出、事件类型、联系人。
- 图表必须同时提供文字数值，不能只依赖颜色区分。

### OCR 导入

- 流程：选择拍照或相册 → 识别中 → 待确认列表 → 批量导入结果。
- 待确认列表允许逐条编辑姓名、金额和日期。
- OCR 结果绝不直接写入正式数据库。
- 明确展示识别失败、低置信度、重复记录和导入失败状态。

### 设置

- 数据备份、恢复、Excel/CSV 导出。
- 主题与字体说明。
- 关于、版本和隐私说明。

## 5. 初始视觉方向

建议使用“温暖、可信、像一本现代家庭礼簿”的方向：

- 基础风格：Material 3，轻量卡片，低装饰密度。
- 品牌色：沿用当前砖红色方向，但定稿前需完成对比度检查。
- 背景：暖白而非纯白，深色模式使用暖黑。
- 金额：收到与送出除颜色外，还必须配合“收到/送出”文字和正负号。
- 圆角：中等圆角，避免过度年轻化或游戏化。
- 动效：只用于保存成功、页面切换和列表变化，保持短且克制。

## 6. 设计令牌命名建议

Figma Variables 与 Compose 代码采用语义命名，不使用页面名或具体色值命名：

- 颜色：`color.brand.primary`、`color.surface.default`、`color.text.primary`、`color.amount.received`、`color.amount.given`、`color.status.error`。
- 间距：`space.1` 至 `space.8`，以 4dp 为基础步进。
- 圆角：`radius.small`、`radius.medium`、`radius.large`。
- 字体：`type.display.amount`、`type.title.page`、`type.title.section`、`type.body.default`、`type.label.action`。
- 模式：至少包含 Light 与 Dark。

定稿后再把令牌映射到 `Color.kt`、`Type.kt`、`Theme.kt`，避免在 Composable 中散落具体数值。

## 7. 原型验收标准

- 新用户能在 3 步内完成一条礼金记录。
- 从首页开始，3 秒内能找到联系人搜索入口。
- 关键按钮包含中文文字，不仅使用图标。
- 所有页面都有空、加载、错误和成功反馈方案。
- OCR 待确认流程可以修改、删除和取消，不直接入库。
- 设计覆盖 Pixel 9 常规尺寸，并检查较大系统字体下的布局。
- 颜色、字号、间距和组件均来自设计变量或组件库。
- Figma 中的最终页面、变量和组件状态足以直接映射到 Jetpack Compose。

## 8. 设计到开发的交付物

设计定稿时应提供：

- Figma 文件链接与版本说明。
- Light/Dark 两套颜色变量。
- 字体、间距、圆角和图标规范。
- 按钮、输入框、金额、记录列表、空状态、错误状态等组件及状态。
- 首页、新增礼金、联系人、联系人详情、搜索、统计、OCR 导入、设置的高保真页面。
- 新增礼金和 OCR 导入两个可点击原型流程。
- 设计验收截图和待开发差异清单。
