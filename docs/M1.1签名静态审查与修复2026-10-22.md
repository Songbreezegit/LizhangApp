## 签名配置审查

- 正式签名配置仍只在 `officialRelease=true` 时创建并绑定给 Release。普通 Release 仍为未签名候选；缺少正式签名配置时不回退 Debug Keystore。
- `verifyOfficialReleaseContent` 原有实现保留；`verifyReleaseSigning` 仍依赖它。`preBuild` 和直接打包/签名任务仍连接签名门禁。
- 正式签名检查要求密钥库在当前工作区及其他带 `.git` 标记的仓库之外，拒绝默认 Debug 文件名、别名和证书主体，要求有效的 RSA 证书且至少 2048 位。
- 同一张公开证书的 DER SHA-256 必须与本人批准的 `signing_certificate_sha256` 相同，才可通过签名门禁。当前该值仍为 `pending`，未进行实际证书比对，不能生成获准正式包。
- 密码只可由未来用户本地构建进程的临时环境变量提供，不能写入 properties、源码、构建参数或日志。当前任务没有输入或读取密码。
- 正式构建在签名资料读取之前拒绝 Gradle 配置缓存。未来本人构建仍须遵循现有 `--no-daemon --no-configuration-cache --no-scan` 操作说明；本次没有执行该命令。

## 备案导出工具审查

`scripts/AndroidFilingInfo.java` 的算法不变：

- RSA 模数直接来自 `RSAPublicKey.getModulus()`，十进制和十六进制是同一正整数的表示，不带 ASN.1 符号填充字节。
- MD5 和 SHA-256 都对同一张 X.509 证书的 `getEncoded()` DER 字节计算，不是 APK 文件摘要。
- 仅接受单张有效的 RSA 公开证书，拒绝弱密钥及常见 Android Debug 身份；不接收密码或私钥。
- 报告中的包名来自项目约定，不能替代最终 APK 清单核对；公开证书导出本身也不表示开发者已批准该签名身份。

`scripts/export-android-filing-info.ps1` 仍只调用 `keytool -exportcert` 导出公开证书，不修改 JKS。密码隐藏输入后仅传给子进程环境，keytool 标准输出和错误均在内存中排空，不打印底层内容；随后释放临时密码缓冲及进程对象。本次仅修改错误提示边界，没有执行脚本、访问 JKS 或重新导出资料。

输出仍固定在受 Git 忽略的 `build/filing/android-filing-info.txt`，先检查忽略规则才导出，只清理本次生成的公开临时文件。成功前不会覆盖历史报告；无网络上传逻辑。脚本会在用户本地终端显示公开报告，运行时应由本人控制终端记录及资料分享。
