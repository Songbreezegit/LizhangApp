# 记一笔保存体验 0.6.0

> 本文保留 0.6.0 历史验收；当前版本 0.7.0 已将保存栏改为通透 Overlay，见 [当前实现与验收](自定义事件与悬浮栏0.7.0.md)。

## 范围与版本

基于 `feat/ui-refresh-v1` 的 `d85521a6c28016b8e648fa99012cfc8a8420c498`，开始前已 fetch 并确认远端一致。本轮只修改记一笔保存区域、保存反馈与返回时序、防重复保存及相关测试。导航栏作为样式参考，没有修改其实现；数据库结构、备份格式、联系人规则和导航架构均未改动。

按本轮明确要求，将工作区已有的版本字段正式更新为 `versionName = "0.6.0"`、`versionCode = 6`，设置页版本文案同步更新。前两轮 UI 文档保留历史验收事实，并注明当前版本。

## 浮动保存栏

`GiftSaveBar` 复用 `GlassTokens.FloatingRadius`、`FloatingAlpha` 和 `glassFrame(shape, floating = true)`，左右 16dp、上下悬浮间距 8dp，玻璃可视高度固定 76dp。内部透明可点击 Row 展示主题橘色 Check 图标和半粗文字；保存中替换为 24dp 进度指示器，容器尺寸不变，禁止重复点击。保存成功到返回期间同样禁止再次提交。

主窗口显式使用 `adjustResize`，避免系统平移与 Compose IME padding 叠加产生底部空白。底部区域统一处理 `imePadding()` 和 `navigationBarsPadding()`，正文消费 Scaffold 的 padding，不再重复处理 IME。成功或失败反馈占据保存栏上方独立空间，Scaffold 将其计入正文可用高度，不覆盖联系人、金额、日期或保存操作；备注可继续滚动到保存栏上方。

## 成功与失败反馈

新增通用 `GlassSnackbarHost`、`GlassSnackbar` 和 `GlassSnackbarVisuals`，使用现有主题玻璃边框、轻阴影、20dp 圆角与正文排版。保留 SnackbarHost 的轻淡入淡出及无障碍时长管理。

- 成功：主题 primary 图标 +「礼金记录已保存」（编辑时为「礼金记录已更新」）。
- 失败：error 图标 +「保存失败，请重试」，容器不使用红色实底。
- 深色：沿用主题深色半透明 surface，不使用 Material 默认黑色 Snackbar。

`GiftSaveFeedbackEffects` 在成功时并行启动反馈和 450ms 计时，返回不再等待 `showSnackbar()` 完整结束。返回标记与单调时钟截止时间使用 rememberSaveable 保留，重组不会重新启动，重建也不会重复返回。短暂停留中屏蔽手动返回，避免与定时返回叠加。

失败事件展示后由 ViewModel 消费，不因重组再次弹出。重试开始时清除失败标志；再次失败可产生新的反馈。失败不会执行返回，也不会清空任何输入。

## 防重复与状态回归

`save()` 在启动协程前同步设置 `isSaving`，堵住协程尚未调度时连续点击的窗口；`isSaved` 也阻止成功后再次创建。保存等待和成功停留期间的字段更新被忽略，避免显示内容与本次实际保存快照不一致。写入失败恢复 `isSaving = false`、`isSaved = false`，完整保留原表单。

单元测试覆盖调度前连续点击、等待中的重复点击、成功后重复点击、失败字段保留、消费反馈和重试成功。设备测试使用独立内存 Room 数据库，真实写入并核对只有一条记录，不接触用户数据。
