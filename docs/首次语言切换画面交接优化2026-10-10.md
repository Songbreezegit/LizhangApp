# 首次语言切换画面交接优化（2026-10-10）

## 问题与修改

用户反馈默认语言第一次切换时短暂黑屏，随后切换正常。本轮继续使用 `fix/privacy-notice-guide-bubbles`，版本保持 `1.0.0-rc2 / 23`。

旧包浅色、深色两轮冷测试都在首次切换采到三张全屏纯黑截图，包含系统栏；同一进程随后切换均为零黑帧。第一次补齐覆盖帧提交后仍复现三张黑帧，真实覆盖提交计数正常。系统日志在黑屏对应时段记录旧 Activity 销毁、新 Activity 恢复，以及 `finishDrawing of relaunch ... 507ms`。这说明内容覆盖本身无法遮住窗口重建的合成交接。

系统 events 中的实际首次重建配置掩码为 `0x2104`，已有声明为 `0x2004`，缺少的 `0x100` 对应 `screenLayout`。仅去掉手动重建仍会被该配置位强制重建。本轮将声明最小补充为 `locale|layoutDirection|screenLayout`，并移除语言配置回调中的手动 `recreate()`，在原 Activity、ComposeView 和导航树刷新资源。未添加方向或屏幕尺寸配置声明。根组合明确读取 `LocalConfiguration`，列表恢复按语言请求和实际资源配置变化触发。

语言变更先等待主窗口取得焦点、捕获旧画面，并在 OnPreDraw 注册实际帧提交回调。覆盖帧真正提交后才应用语言；完整目标资源、导航、设置列表位置、窗口焦点和新帧提交就绪后再淡出覆盖。发生其他实际 Activity 重建时仍安装新的 ComposeView 和视图树所有者，只替换实时页面并保留覆盖树。

语言重建中的临时 Insets 尺寸变化允许覆盖缩放铺满窗口；主题圆形变化仍按原尺寸规则取消。关闭系统动画时语言变化仍进行画面冻结与真实帧交接，不添加固定等待。捕获失败与超时仍提交已接受的目标并释放状态。

本轮没有修改 Room、隐私选择、联系人、备份或记一笔导航及保存栏的既有设计。

## 验证方式

新增 `FirstLanguageTransitionInstrumentedTest`，每轮在专用 `emulator-5620 / LizhangFreshUiApi36` 清空测试应用数据并启动独立冷进程；启动前不设置任何 AppCompat 或 Android 应用语言，不预先执行 PixelCopy。通过实际设置导航及语言弹窗从跟随系统第一次选择语言，再次切回对照。

该用例核对 Activity 身份、完整资源语言、窗口焦点、导航、列表位置和覆盖状态，并连续采集系统合成截图。旧包必须实际重建一次；修复包必须保持同一 Activity 和宿主数量，不能取消身份检查。修复包另外要求 `languageCoverCommits` 每轮增加一次，排除仅依靠超时降级通过的情况。反射读取该计数使同一测试 APK 可用于缺少该字段的旧包对照。独立的显式重建和返回导航验证记录与首次语言采帧分开。

初次基线运行在进入设置前因测试误用文字定位导航而失败。实际入口只有无障碍描述；已按失败现场改为现有可点击的设置导航锚点，并保留原失败证据，没有改变黑屏或空屏判据。

系统截图采样并非逐刷新帧录制，采样时序明确记录最大间隔。专用模拟器的结果不代替用户物理设备首次切换验收。本轮没有对连接的真实手机安装、清除或操作。
